Clockwise 主题应用开发手册

本文对应 Lua 运行 API 1、CWP2 应用包和固件0.9.3新增的应用元数据功能。编写时先使用 examples/hello-clock，再逐步加入素材、分关加载和交互。包格式细节见 主题应用格式。

1. 先区分四种文件

文件或目录用途是否建议手工编辑
含 theme.json 的文件夹应用源码，包含 Lua、图片和数据资源是，推荐从这里开始
同一文件夹的 ZIP可编辑源码的便携分发形式解压后修改
.cwp安装到设备的应用包，包含运行源码、资源目录、元数据和可编辑归档不直接编辑二进制，修改源码后重新打包
工坊导出的 v3 .json浏览器工程，保存编辑器状态、精灵定义和源代码也可编辑；与 theme.json 的包清单不同

.lua 单文件也可导入，但缺少完整包身份和设备需求声明，不适合正式发布。themes/gallery/*.json 是内置主题的工程源，旁边的 .lua 和 themes/apps/*.cwp 是构建输出；修改构建输出会在下一次构建时被覆盖。

2. 五分钟制作第一个时钟

在 theme-studio 目录打开终端：

powershell
npm install
npm run dev

打开 本地主题工坊，点击“导入文件夹”，选择 examples/hello-clock。主题固定为 64×64；点击“运行”，或者按 Ctrl+Enter。电脑预览使用电脑时间，A/B 预览按钮模拟输入。

示例包含每秒换色、缓慢移动的星点、时间和日期。A 键换色，B 键隐藏或显示星点。它不依赖图片、录制动画或外部服务。

打包和检查：

powershell
node tools/theme-app.mjs pack examples/hello-clock --out .build/hello-clock.cwp
node tools/theme-app.mjs check .build/hello-clock.cwp
node tools/theme-app.mjs check .build/hello-clock.cwp --device http://172.16.11.5

最后一条命令只读取设备能力并检查兼容性，不上传、不切主题。结构检查通过也不代表完成实机内存和帧时间测试。

浏览器预览的源码上限为256KiB，设备仍按实际能力限制，例如无PSRAM经典ESP32常为64KiB、当前有PSRAM的S3为256KiB。因此“在工坊可以运行”不等于“可以安装到所有设备”。浏览器目标帧率可设为1..60，但本例从30FPS起步。

设备后台 → “主题应用” → “安装应用文件或主题文件夹”，选择生成的 CWP、源码 ZIP 或文件夹。安装后可离线运行。应用身份相同时更新原应用；需要保留旧应用和新包同时存在的存储空间。请先导出自己的源码备份，再修改发布。

精简清单示例：

json
{
  "format": "clockwise-theme-package",
  "version": 1,
  "id": "hello-clock",
  "packageName": "org.clockwise.examples.hello-clock",
  "title": "星点时钟",
  "appVersion": "1.0.0",
  "description": "低内存时钟，每秒换色并缓慢移动星点。",
  "author": "你的名字",
  "runtimeApi": 1,
  "width": 64,
  "height": 64,
  "fps": 30,
  "entry": "main.lua",
  "scripts": [],
  "assets": [],
  "media": [],
  "resources": [],
  "data": {},
  "requirements": {
    "chips": ["esp32", "esp32s3"],
    "psramBytes": 0,
    "luaHeapBytes": 49152,
    "luaWorkingBytes": 32768,
    "graphicsBytes": 12288,
    "targetFps": 30
  }
}

version 是源码包清单格式版本，appVersion 是你发布的应用版本，runtimeApi 是所需的固件 API 版本；三者含义不同。packageName 是稳定身份，后续升级保持不变；换显示名称和版本号不应生成新包名。id 保留给资源与旧工程兼容，不能用安装槽位编号代替应用身份。

requirements 是作者声明的需求，不是自动测量结果：

  • chips 使用芯片系列名，PSRAM 要单独声明；S3 型号不代表一定装有 PSRAM。
  • psramBytes 是需要的 PSRAM 字节数，0 表示应用不强制要求 PSRAM。
  • luaHeapBytes 指加载、编译、初始化阶段的 Lua 分配峰值需求。
  • luaWorkingBytes 指持续运行阶段的 Lua 分配需求，给临时字符串和 GC 留余量。
  • graphicsBytes 指原生绘图资源及相关工作内存需求，不能把图片文件大小直接填在这里。
  • targetFps 是请求的主题执行频率；CPU、素材解码、Wi-Fi 共存仍会影响实际帧时间。较低频率不等于一定不卡顿。

数值都以字节计。不要用过小声明绕过检查；安装时的初始化验证也无法覆盖游戏全部关卡和所有随机路径。设备兼容与运行性能是两项检查。

4. Lua 生命周期

主题可定义以下全局函数，未定义的回调会跳过：

lua
function start() end
function update(dt_ms) end
function draw() end
function second() end
function minute() end
function button(key) end

加载顺序为：定义精灵 → 执行库和 scripts（按清单顺序）→ 执行入口 Lua → 缓存回调 → start() → 第一次 draw()。以后更新时先检查秒、分钟变化，依次触发 second()、minute()、update(dt_ms)，随后绘图。第一次更新也会触发秒和分钟回调；第一次绘图前还没有触发它们，所以文字缓存应在 start() 中初始化。

update 的参数为经过的毫秒数。固件和预览的正常调度会限制单次过大步长，但不保证每一帧恰好 16.67 ms。按 位置 += 速度 * dt_ms / 1000 移动，别按“一帧移动几个像素”计算速度。

回调在加载时缓存。运行中把 draw 重新赋成另一个函数不会替换已缓存的回调；请在原 draw 内根据状态分支。没有 stop() / destroy() Lua 回调；切换或卸载主题时，运行时会释放该应用的 Lua、精灵、图层和动画缓存。

scripts 是按顺序执行的独立 Lua 段。每个文件的顶层 local 只在该段中可见；跨文件共享内容应放在明确的全局命名表中，例如 scene = {}。沙箱没有 require()，也不会把模块顶层 return 值自动注册成库。

5. 坐标、颜色、字体和数字

  • 左上角为 (0,0)，有效像素坐标为 0..63，x 向右、y 向下。
  • 绘图颜色可用 RGB565 整数，如 0xffff，或字符串 "#RRGGBB"。高频绘图优先使用已计算的 RGB565 整数。
  • gfx.text 是小型 ASCII 像素字体，小写按大写处理；不支持完整中文。font.draw("menu12",...) 只包含固件预生成的中文子集，缺字不能靠传入任意 Unicode 自动补齐。
  • 字体 ID 包括 mario、segment、sans、bold、italic、pixel、thin、menu12。各字体的字形集合不同，数字字体不保证覆盖英文字母。
  • 原生固件采用 32 位整数和单精度 Lua 浮点配置。浏览器的数值实现与原生精度不完全相同；大整数、连续长时间累计值和浮点边界需要实机验证。
  • Lua 表和精灵帧从 1 编号；二进制资源读取偏移从 0 开始。

6. 原生绘图 API

下表中的 color 均接受上述颜色形式。除特别说明外，函数无返回值。

gfx.pixel(x,y,color)绘制一个像素
gfx.rect(x,y,w,h,color)填充矩形
gfx.outline(x,y,w,h,color)一像素宽矩形边框
gfx.line(x1,y1,x2,y2,color)绘制线段
gfx.circle(x,y,r,color)填充圆形，半径被限制为 0..64
gfx.triangle(x1,y1,x2,y2,x3,y3,color)填充三角形
gfx.gradient(x,y,w,h,top,bottom)垂直渐变填充

7. 精灵和图层

可编辑精灵

在清单中引用 JSON：

json
"assets": ["assets/hero.json"]

assets/hero.json 最小示例：

json
{
  "id": "hero",
  "width": 3,
  "height": 3,
  "palette": ["#ff4040", "#ffffff"],
  "frames": [".0.010.0."],
  "encoding": 4
}

一位十六进制编码中 0..f 是调色板下标，. 是透明；每帧必须恰好 width*height 个像素。encoding:8 时每像素使用两位十六进制，透明写成 ..，每帧字符串长度为 width*height*2。颜色必须为 #RRGGBB，帧尺寸最大 64×64、每个精灵最多 32 帧、每主题最多 16 个精灵。

也可直接引用 PNG 帧：

json
"assets": [
  {"id":"hero","frames":["assets/hero-1.png","assets/hero-2.png"]}
]

同一精灵的 PNG 帧尺寸必须一致且不大于 64×64；透明 alpha 小于 128 的像素会转成透明，其余像素合计最多 255 色。浏览器通过 createImageBitmap 和 OffscreenCanvas 转换 PNG。当前Node CLI不直接解码PNG，遇到它会给出转换提示；先用浏览器工坊导入，再导出包含精灵JSON的源码包，或者自行预处理成精灵JSON。

API说明
sprite.draw(id,x,y,frame=1,scale=1,flip=false)绘制精灵；帧号循环，缩放 1..4；flip 为水平翻转
sprite.frames(id)返回帧数，未知 ID 报错
sprite.tilemap(id,map,columns,x=0,y=0,packedRows=0)绘制可见图块；默认 map 为十六进制字符串，0 留空、1..f 为精灵帧号
assets.define(id,w,h,palette,frames,digits=1)底层精灵定义；调色板颜色以逗号分隔，帧以 | 分隔，digits 为 1 或 2。通常由打包器生成，无需手写
layer.save(id)保存当前整屏快照；最多 2 个缓存图层，每个 8192 字节
layer.draw(id,x=0,y=0)将快照画到指定位置

普通 tilemap 字符串长度须整除 columns，列数最多 4096、总字符串最多 65536 字节。压缩形式设置 packedRows>0，map 为每像素半字节的二进制字符串，字节数须为 ceil(columns*packedRows/2)，行数最多 8192。使用 resource.rle4(data,true) 可生成这种数据。

打包器对解码精灵像素使用 48 KiB 预算；原生底层另有包含调色板的 64 KiB 资源上限。这些是结构上限，低内存主题应远低于上限。图层缓存虽然省 CPU，也会占用内部内存，简单背景直接重画常常更合适。

原生粒子

lua
function start()
  fx.create("snow", 16, 0, 0, 64, 64, 0, 4, 0xffff, "point")
end
function draw()
  gfx.clear(0)
  fx.draw("snow")
end

fx.create(id,count,x,y,w,h,vx,vy,color,style) 建立一组粒子；最多4组，每组数量限制为1..128，区域宽高1..64，速度为每秒像素。style 支持 point、rain、spark，其它字符串按点样式处理。fx.draw(id) 绘制已有组，位置由宿主按dt自动更新；不要每帧重新create。每个粒子原生参数约12字节，加组结构和分配开销。

8. 录制动画和自定义资源

清单通过以下字段声明：

json
"media": [{"id":"water","path":"media/water.cwa"}],
"resources": [{"id":"levels","path":"resources/level-data.cwr"}]

media 最多 2 个，连同 resources 总计最多 8 个文件。资源 ID 最长 31 个 ASCII 字符，只用字母、数字、_、-；动画 ID 使用小写字母、数字和 -，有助于同时满足浏览器校验。

API返回值/作用
media.draw(id,x=0,y=0,ms=clock.millis())在原生动画解码器中绘制 CWA，不在 Lua 中逐像素解码
media.release(id)释放该动画的运行解码缓存，后续可重新加载
resource.size(id)原始资源字节数；不存在时报错
resource.read(id,offset,count)读取二进制 Lua 字符串；偏移从 0 开始，单次最多 8192 字节，不能越界
resource.rle4(data,packed=false)每个输入字节：高4位为重复次数减1，低4位为图块值；输出最多8192个图块值。普通模式输出 0123456789abcdef 字符串，packed 模式输出半字节数据
memory.collect()完整回收不再使用的 Lua 对象，返回当前 Lua 分配字节数；原生图形内存不计入此数值

动画时间戳为 0..4294967295，文件内按总时长循环。CWA 只支持 64×64、最多 256 帧、每 16 帧设置关键帧。优先使用 CWA2 索引色：原生绘制可用 4096 字节索引帧缓存加调色板；CWA1 的 RGB565 帧缓存为 8192 字节。流式读取时还需帧索引表（每帧16字节）和512字节读取缓存，具体总量见实机 graphicsBytes。

.cwr 是任意二进制资源容器，没有强制的关卡协议。脚本与数据必须自行约定版本、偏移和编码。大型地图应有小型目录，按关/区段读取，不要把整个世界解压成 Lua 表。

lua
local segment
local function loadSegment(offset, bytes)
  segment = nil
  memory.collect() -- 仅在场景切换等明确边界执行
  local compressed = resource.read("levels", offset, bytes)
  segment = resource.rle4(compressed, true)
end

resource.read 返回新字符串，并非零拷贝引用。逐帧读取8KiB再切片会反复分配；尽量让一个区段在场景内复用，切换场景时释放。media.release 只释放对应解码器，不承诺清除固件对整个包的 PSRAM 资源缓存。

9. 时间、随机数、数据和输入

API说明
clock.format(format)支持 %H、%M、%S、%d、%m；不是完整 strftime，不支持的序列原样保留
clock.value(field)本地时间字段：hour/minute/second/day/month/year/weekday/millisecond；weekday=0为周日
clock.utc(field)UTC字段：hour/minute/second/day/month/year/weekday/yearday；yearday从1开始
clock.millis()主题加载后的累计更新毫秒；原生32位计时有长时间边界，周期动画优先自行维护有界 phase
rng.seed(seed)设置 xorshift32 种子；参数为 uint32 范围整数；0 使用固定非零回退
rng.int(lo,hi)闭区间随机整数；参数向下取整，跨度最多1000000
rng.float()[0,1) 随机数
data.get(key,fallback)读取宿主缓存数据，不执行网络访问；不存在时返回 fallback（可为 nil）
input.pressed(key)查询当前按键状态，当前设备宿主识别 A、B
telemetry.set(key,value)提交调试状态；number、string、boolean。不要用它当保存接口

随机种子默认由宿主产生。固定种子可复现实验，但同一序列还依赖调用次数一致。使用 rng 而非 math.random，才能尽量保持电脑与固件一致。

温湿度示例：

lua
local temperature = data.get("temperature", nil)
if temperature then
  -- 建议在 second() 中生成文字缓存，而非每帧 format。
end

当前板级宿主只有已接入传感器时才提供有效温湿度；没有读数时应显示 --，不要把默认22℃冒充测量值。theme.json.data 目前用于电脑预览的示例数据，不能当成会自动写进 ESP32 的任意持久化配置。原生宿主当前的 message 是固定示例文本；天气服务、任意用户配置和网络数据源需要后续宿主接口支持。

浏览器调试面板可展示任意 telemetry 键；当前 ESP32 的状态接口只汇总数值 level/area/deaths/coins 等已接入指标，任意字符串键不会自动出现在后台。输入也受硬件和固件映射限制，声明 A/B 回调不代表板上已经连接了物理按钮。

10. 原生寻路和可选 Lua 工具库

lua
local distances = nav.bfs(3, 3, ".........", 1, true)
local d = nav.at(distances, 9)
  • nav.bfs(w,h,map,start,packed=false)：四邻接无权距离，最多256格，#为墙；map字节数必须等于w*h，起点从1编号。
  • nav.solve(w,h,map,start,costs,packed=false)：返回距离、第一步、父节点三份结果。costs为Lua数组，缺省代价1，允许0..1000000整数。
  • 普通模式返回表，不可达格子为nil；packed模式返回紧凑二进制字符串，通过 nav.at(result,index) 读取，不能直接当Lua数组索引。
  • nav.at(result,index)：返回该格值，不可达为nil。数据宽度由编码头决定，不能混用别的字符串。

util 不是固件原生全局库。需要时把 themes/lib/core.lua 复制到自己目录中的 scripts/core.lua，并加入清单 scripts：

json
"scripts": ["scripts/core.lua", "scripts/scene.lua"]

该库提供 util.clamp(v,lo,hi)、util.lerp(a,b,t)、util.wave(ms,period,lo,hi)、util.frame(ms,fps,count)、util.every(id,interval)。every 第一次调用只登记计时器并返回false，不会立即触发；相同 ID 共享计时器。

11. 低内存设备的编写方法

以无 PSRAM 的经典 ESP32 为例，固件既要为 DMA 扫描、Wi-Fi、HTTP、Lua 和原生绘图资源分配内存，还要面对连续块碎片。源码大小、CWP文件大小、Lua实际分配量是三个不同的量。

优先采用避免
在 start 中建立固定大小表，在 update 中修改数值每帧生成新表、拼接字符串、格式化时间
second/minute 中缓存文字draw中反复 clock.format / string.format
原生 font、sprite、tilemap、粒子接口Lua逐像素循环画大面积复杂图像
每关或每区段的紧凑字符串/二进制数据一次把32关地图展开成多层Lua对象
小型索引色精灵、必要时才打开动画同时缓存多个全屏背景、动画和地图副本
阶段结束后丢引用并在切换边界 collect每帧强制完整GC，或长期保存无用对象
可见区域裁剪、只更新有变化的状态每帧全地图寻路、频繁资源读取

图层每个8KiB，两个就是16KiB；粒子每个位置和参数在原生侧约12字节；这些不会全部出现在Lua内存统计里。PSRAM允许更大资源缓存和Lua堆，但不会把240MHz CPU变快。需要大内存的主题应明确要求 PSRAM，不能仅因为它在电脑上运行顺畅就标为所有设备适用。

先用30FPS和少量素材达成效果，再决定是否需要60FPS。每帧总时间预算约为 1000 / FPS 毫秒；60FPS约16.67ms，30FPS约33.33ms。设备性能指标中的 computeUs、dmaUs、maxUs、late、missed 分别帮助区分计算、画面提交、峰值耗时和调度问题。累计计数要比较同一主题、同一时间段的增量，不能把切主题/上传暂停产生的遗漏直接归因于动画。

固件0.9.3会将CWP2的目标频率用于主题执行调度；这不改变HUB75的DMA扫描刷新率，也不保证每帧都能按时算完。Fengari使用JavaScript对象和不同的分配器，它的浏览器堆占用不能换算成ESP32的Lua字节数。

声明的需求只能做安装前筛选。发布前应在目标硬件上覆盖初始化、场景切换、最复杂场景、随机动作以及打开后台的情况，记录版本、Lua峰值/稳定占用、graphics占用、最低内部空闲量、最大帧时间和观察时长。没有这些实测记录时应标记未验证，不写“零掉帧”“适用所有ESP32”。

13. 沙箱、发布和升级

固件开放 Lua 基础函数、math、table、string 及本手册的宿主API。io/os/package/debug、文件访问、网络、GPIO、dofile/loadfile/load/require、collectgarbage/pcall/xpcall/print 不作为主题可用接口；时间和回收使用专用API。主题不能自行下载数据、写入NVS或改变系统设置。

保留源码文件夹和版本记录；每次发布增加 appVersion，保持 packageName。固件内部仍可能使用数字槽位用于保存调度，应用作者和用户操作应优先使用稳定包名，不能认为槽位在不同设备上恒定。

从旧主题迁移时，保留原Lua和资源，在 theme.json 增加元数据和真实需求，重新打包CWP2。旧CWP1或单Lua继续属于兼容输入，但没有完整声明时不能自动推断为经过兼容性认证。新版包格式与旧版固件的支持不同，升级前先确认固件支持CWP2。导出源码是修改入口，导出应用是部署备份入口；二进制应用不直接手工改偏移。

目前这套接口覆盖64×64动画时钟、分层精灵、地图、粒子和分段数据主题；它不是通用桌面应用系统，也没有任意网络、任意中文字体、权限管理或任意用户配置存储。需要这些能力时应明确增加宿主API和运行API版本，再实现浏览器与固件两端的一致行为。

Clockwise 源码包与 CWP 应用格式

开发入门见 主题应用开发手册。本文件面向打包器、固件和工具作者；普通主题作者优先编辑源码文件夹，不手写CWP二进制。

1. 三层职责

  1. 源码包：文件夹/ZIP，根清单为 theme.json，包括脚本和可编辑素材。
  2. 安装包：CWP2，保存小型可直接读取的应用元数据、合并Lua、资源目录和可编辑归档；固件无需为读取包名而解压整个ZIP。
  3. 运行时：Lua API 1 + 原生绘图引擎，按需读取资源，并执行应用声明和设备实际能力检查。

packageName 是跨设备稳定身份；title 是显示名称；appVersion 是发布版本。固件可保留数字安装槽位服务内部文件和既有调度，但用户不应依赖相同包在不同设备上的槽位编号一致。按包名进行运行、卸载和导出，才能避免删错应用及升级身份漂移。

2. 源码清单

根清单格式名为 clockwise-theme-package，version:1，固定 width:64,height:64。

字段含义
id旧工程/资源兼容ID；新应用也保留它
packageName稳定、命名空间式应用身份，例如 org.example.clock.stars
title用户看到的名称
appVersion应用版本，例如 1.0.0；与格式版本分开
description / author描述和作者，不是来源/版权授权证明
runtimeApi请求的主题运行API版本，当前为1
fps源码工程的目标帧率
entry入口Lua相对路径，省略时为 main.lua
scripts需要按顺序执行的其它Lua文件相对路径，最多32个
assets精灵JSON路径或 {id,frames:[PNG路径...]}
media{id,path} 动画文件，最多2个
resources{id,path} 任意二进制数据；与media总共最多8个
data浏览器预览的示例数据；当前并不是任意设备配置存储
requirements芯片、PSRAM、Lua加载/运行、原生图形内存和目标帧率需求

身份和元数据限制：

  • packageName 最多63个UTF-8字节，实际只接受小写ASCII命名空间：^[a-z][a-z0-9-]*(?:\.[a-z][a-z0-9-]*)+$。
  • id 最多32个ASCII字符：^[a-zA-Z0-9_-]{1,32}$。
  • appVersion 为语义化版本（例如 1.0.0），最多31个UTF-8字节。
  • title 最多96个UTF-8字节、description 最多384字节、author 最多64字节；中文通常每字3字节，不能把字节数当字符数。
  • runtimeApi 为正整数，当前默认1。
  • requirements.targetFps 为1..60整数，与清单 fps 保持相同；导入导出以需求中的目标频率同步工程值。

生成的CWP2元数据还包含 requirementsDeclared 和 verification:{"status":"unverified"}。PSRAM为0合法；Lua加载、Lua工作、graphics三个正数齐全才视为完整需求声明。内存为0表示未知，不能解释成应用不使用任何内存。PSRAM比较会将设备实际报告值向上圆整到MiB，避免8MiB芯片的可用堆因管理开销略小于标称容量而错误拒绝。

所有路径相对于 theme.json 所在目录；不能使用绝对路径、反斜杠、空路径段、. 或 ..。ZIP可以带一层共同目录前缀，但必须且只能定位到一个 theme.json。文件总数最多300；压缩体/解压体限制按目标设备能力对应的导入配额检查，导入和打包阶段还要检查真实合并脚本、归档和总包大小。

精灵定义会被打包器转成 assets.define Lua段。库和模块按原顺序拼接，以保留跨文件的执行顺序。合并源码使用保留标记：

text
-- @cw-bundle 1
...第一段...
-- @cw-part
...下一段...

作者源码不能包含完整的保留分隔标记。固件按段读取编译并回收临时对象，避免一次持有所有精灵字面量和所有编译临时数据。分段并不让永久Lua对象或原生精灵免占内存。

3. CWP2 二进制布局

所有整数均为无符号、小端。包内容按下表连续排列，中间没有隐式对齐或空洞。

文件偏移长度内容

44sourceSize：运行Lua字节数

124resourceCount：资源目录项数，0..8

204flags：本版为0，未知标志不能静默解释

每个资源目录项为40字节：

项内偏移长度内容
032ID，ASCII，最长31字节，NUL终止并补零

元数据字段为 packageName/id/title/appVersion/description/author/runtimeApi/requirements/requirementsDeclared/verification。固件应从包内元数据读取身份，不能相信上传URL中另行提交的标题/包名覆盖真实身份。资源ID必须唯一；每个offset必须等于前一内容的末尾，最后一资源末尾必须等于文件总长。检查加法溢出、截断、重叠和多余尾部。

示例计算：

text
metadataOffset = 24 + resourceCount * 40
sourceOffset   = metadataOffset + metadataSize
archiveOffset  = sourceOffset + sourceSize
resource0Offset = archiveOffset + archiveSize

文件大小上限来自设备能力和存储分区，不能只由芯片名称决定。无PSRAM设备仍可能没有足够连续内部内存运行一个结构合法的小包；带PSRAM设备也不能忽略DMA/Wi-Fi所需的内部内存。

4. 旧包兼容

CWP1 的前16字节依次为 CWP1/sourceSize/archiveSize/resourceCount，然后是相同的40字节资源目录、Lua、ZIP和资源，没有独立元数据段。

旧CWP1/单Lua可以继续作为兼容输入，但缺少完整应用需求时，兼容状态应为未知或未声明，不能当成已通过设备性能认证。升级方式是从可编辑ZIP或源码文件夹增加清单字段后重新打包CWP2。旧固件如果只识别CWP1，不能安装CWP2；runtimeApi:1 不代表旧固件已经识别新的二进制容器。

CWP内保存ZIP和运行资源意味着可能存在素材重复：ZIP保留可编辑原件，资源尾部提供固件直接定位的运行数据。这主要占Flash，不等于运行时会把ZIP解压到RAM。低存储设备应减少归档素材、录制动画时长和重复资源，而不是通过删除任意字节破坏格式。当前 flags:0 不能表达“去掉归档”。

5. CWA1 / CWA2 动画格式

动画固定64×64。所有多字节数值小端。

16字节头：

偏移类型内容
04字节CWA1 或 CWA2
4u16width=64
6u16height=64
8u16帧数，1..256
10u16CWA2调色板颜色数1..256；CWA1此项不作为调色板解释
12u32整段总时长，毫秒，必须大于0

头后为 帧数 * 16 字节索引。每项依次为4个u32：数据偏移（相对帧数据区）、数据字节数、该帧结束的累计毫秒、关键帧标志0或1。结束时间严格递增，最后一个结束时间等于总时长。第0、16、32……帧必须是关键帧。单帧编码数据不超过16384字节。

CWA2索引表后有 颜色数 * 2 字节RGB565调色板，随后才是帧数据区；CWA1直接进入帧数据区。帧中一条操作以u16开头：低14位为长度n（必须大于0）；高两位定义操作。

高位操作
0x0000字面量：随后n个颜色值
0x4000重复：随后1个颜色值，重复n次
0x8000保留上一帧对应n像素，不跟颜色；关键帧禁止使用
0xc000无效

CWA1颜色值为2字节RGB565；CWA2为1字节调色板下标。每帧操作覆盖恰好4096像素，不能越界。随机跳转时从同组关键帧解码，最远回溯15帧，文件帧率与屏幕刷新率不是同一概念。

CWA2在固件绘制路径中可直接用索引帧和调色板，避免总是分配RGB565转换帧。缓存只在使用时分配，可通过 media.release 释放解码器。电脑预览和设备内存实现不同，不能用浏览器对象大小当作设备占用。

6. CWR 与图块数据

.cwr 不规定通用头或压缩算法，是作者定义的二进制数据。建议自定义小头：魔数、版本、条目数量以及每条数据的偏移/大小；在Lua中先读取目录，再按关或区域读取内容。

原生 resource.rle4 的单字节编码为：(重复次数减1)<<4 | 图块编号，重复次数1..16、图块编号0..15。普通模式输出十六进制字符，packed模式每字节放两个图块值，先低半字节后高半字节。解码图块数上限8192。

tilemap普通字符串用 0 留空，1..f 对应精灵的1..15帧；packed数据配合 packedRows 明确行数。RLE数据格式不会自动实现碰撞、寻路、怪物行为或关卡切换，这些由主题Lua处理。

7. 兼容性与性能声明

安装筛选至少分别检查：容器结构/大小、运行API、芯片系列、PSRAM、Lua加载配额、Lua工作配额、原生图形需求、实际存储余量。仍需在真正初始化时观察分配失败，声明不能替代分配器。

compatible 只能表示声明的静态需求没有超过当前设备能力；unverified 表示尚未完成目标设备上的性能验证。实测记录应包含应用包名/版本、固件版本、芯片和PSRAM、观察时长、覆盖场景、Lua峰值及稳定值、原生图形量、帧时间和丢帧计数增量。作者自行填写的目标FPS、估计内存或“已测试”文字不能自动成为设备认证。

整个游戏32关的最坏情况可能不在启动画面。安装时只执行初始化和首帧，不能据此承诺所有场景不卡顿。电脑结构检查、Fengari预览、原生初始化和实机长时间场景测试应分别报告。

8. 按稳定身份管理应用

支持新应用接口的固件提供：

请求参数
GET /api/apps返回安装项、元数据、兼容状态、设备能力和存储余量
POST /api/apps/installmultipart上传CWP；由包内元数据决定身份并查找更新位置/空槽

PowerShell运行示例：

powershell
Invoke-RestMethod -Method Post -Uri 'http://172.16.11.5/api/apps/run' `
  -ContentType 'application/x-www-form-urlencoded' `
  -Body @{ packageName = 'org.clockwise.examples.hello-clock' }

卸载同一应用时将URL末尾 run 改成 uninstall。卸载正在运行的主题会回到基础时钟并清理相关计划，因此命令应由用户针对自己安装的应用执行。

串口命令一行一个JSON，115200波特率：

json
{"cmd":"apps"}
{"cmd":"app.run","packageName":"org.clockwise.examples.hello-clock"}
{"cmd":"app.uninstall","packageName":"org.clockwise.examples.hello-clock"}

id和旧 index也保留兼容，但发布文档不应把某个槽位编号当作应用的稳定身份。

传感器主题 API 2 / Sensor Theme API 2

新增八套传感器主题固定为 64×64、30 FPS，要求 runtimeApi:2 与 requirements.chips:["esp32s3"]。芯片系列不代表传感器一定存在：温湿度主题另声明 requirements.sensors:["temperature","humidity"]，重力主题声明 requirements.sensors:["imu"]。安装器检查能力，运行期间仍检查有效性。旧 API 1 固件不能据此视为兼容。

The eight new themes target 64×64 at 30 FPS, require runtimeApi:2, and declare requirements.chips:["esp32s3"]. A chip family does not establish sensor presence: climate themes also declare requirements.sensors:["temperature","humidity"], and gravity themes declare requirements.sensors:["imu"]. Installation checks capabilities; runtime code must still check validity. API 1 firmware is not assumed compatible.

不要把 fallback 0 当作有效测量。设备未接入、采样失败或过期时，应显示 -- / NO IMU 并暂停依赖该样本的动作。浏览器预览中，undefined、null、NaN、无穷数都按缺失值返回 fallback。支持能力与样本有效性分别表示“有硬件”和“此刻有可信读数”。

Do not treat a fallback of 0 as a valid measurement. Show -- / NO IMU and pause dependent motion when a sensor is absent, sampling fails, or a sample is stale. Browser preview returns fallback for undefined, null, NaN, and infinity. Capability and validity distinguish hardware presence from a usable reading at this instant.

屏幕坐标 / Screen coordinates

令原轴加速度为 a，初始重力为 b=(-a.x,-a.y,-a.z)。屏幕旋转只映射 x/y；z 保持 b.z：

Let raw acceleration be a, and initial gravity be b=(-a.x,-a.y,-a.z). Rotation maps x/y while preserving z as b.z:

Rotation(gravity_x, gravity_y)
0°(b.x, b.y)
90°(b.y, -b.x)
180°(-b.x, -b.y)
270°(-b.y, b.x)

固件低通时间常数约 250 ms，IMU 样本超过 500 ms 视为无效。自动方向还需稳定姿态与滞回，不是每次过零立即旋转。传感器安装方向与面板零度基准仍需在实际板上确认；主题不应私自再次旋转 gravity_x/y。重力可受动态线性运动影响，不是陀螺融合后的绝对姿态。

Firmware uses a low-pass time constant of approximately 250 ms and treats IMU samples older than 500 ms as invalid. Automatic rotation requires a stable pose and hysteresis; it does not rotate immediately on each sign change. Sensor mounting relative to panel rotation zero still needs confirmation on the physical board. Themes must not rotate gravity_x/y a second time. Dynamic linear acceleration can affect the gravity estimate; it is not a gyroscope-fused absolute attitude.

模拟器 / Simulator

工坊“模拟数据与按键”提供温度、湿度与独立有效性开关，以及 IMU 支持/有效、三轴加速度、三轴角速度、屏幕方向和左右倾斜/平放预设。所有输入明确标为手动模拟。取消某项有效性会移除对应数值键；不以零值冒充缺失样本。模拟器按上表立即计算屏幕重力，不模拟硬件低通延迟、采样总线或自动方向稳定判定；方向选择是手动模拟。

The studio's “Simulation data and buttons” panel provides temperature and humidity with independent validity controls, IMU support/validity, three acceleration axes, three gyroscope axes, screen rotation, and left/right/flat presets. Inputs are explicitly labeled as manual simulation. Disabling validity removes the related numeric keys instead of substituting zero. The simulator immediately computes screen gravity using the table above; it does not emulate hardware filter delay, sampling buses, or automatic-rotation stability decisions. Its rotation selector is manual.
